# 诗词射覆

本地运行的 React + TypeScript 诗词游戏。支持两人共用一台设备轮流出题，也支持一人与本地系统对战。游戏运行时只读取项目内的静态题库，不连接在线判题服务。

## 启动

需要 Node.js 20.19+ 和 pnpm 12。项目自带精简题库；首次启动无需重新下载诗词数据。

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

浏览器打开终端显示的本地地址，默认是 `http://127.0.0.1:5173/`。

生产构建和规则测试：

```powershell
pnpm build
pnpm test
```

## 玩法

出题者提供上一句诗、目标字数和指定字。指定字**不能**出现在上一句中。答题者给出的新句须具有指定字、与上一句共享至少一个其他汉字、符合目标字数，并被题库收录。标点和空格不计字数，繁简体可互通；答案不受出题者私有参考答案限制。

答对得 1 分，并将答句带入下一轮。主动揭晓一条参考答案视为本题失败，原出题者重新出题。超时也不计分。本地双人模式中，格式正确但题库未收录的答句可以提交双方复核；系统模式无法人工核实未收录诗句，会提示继续修改或揭晓参考答案。

单人模式的系统对手使用同一套本地题库和出题规则。难度控制系统答题成功率：轻松 55%、标准 72%、挑战 90%。系统未答出时，本题失败并由原出题者重新出题。

本机通过 localStorage 保存当前对局快照，使用 IndexedDB 缓存诗词分片和已结束对局。刷新后可继续，结算页支持导出文本记录。请不要清除浏览器站点数据，以免丢失本地存档。

点击题面或结果中的“出处”可在弹窗中查看对应全诗。全诗随项目离线提供，首次查看时按来源文件加载。

顶部“繁體 / 简体”按钮可切换诗句、线索、出处及全诗的字形，也会转换当前未提交的输入内容。简体和繁体作答使用同一套判题规则；字形选择保存在本机，刷新后仍然有效。

## 题库与来源

题库由 [chinese-poetry/chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) 的固定提交 `b8594f81a89752241442f2ce267d6f66f96704ee` 构建。导入范围为唐诗、宋诗、宋词各两份 JSON 文件，共 6,000 条作品记录，生成 54,511 条去重诗句。此题库是可玩版本的精选范围，不代表仓库的完整诗词收录；未命中不等于诗句不存在。

`data/source-manifest.json` 锁定原始文件与提交；`scripts/build-corpus.mjs` 可重建长度分片、来源索引和质量报告。重建时运行：

```powershell
pnpm corpus
```

该命令会从上述固定提交下载源 JSON，写入被 Git 忽略的 `data/cache/`；生成的诗句和全诗分片位于 `public/corpus/`。`data/quality-report.json` 记录导入数量、重复和过滤情况。分发时保留了原仓库的 MIT 许可文本 `public/corpus/LICENSE.txt`，并在每条诗句中记录源文件、作品索引、作者与题名。

## Git

本项目使用本地 Git 仓库，源码、锁文件、构建脚本、固定数据版本和游戏题库已纳入版本管理。`node_modules/`、`dist/`、测试输出与原始数据缓存由 `.gitignore` 排除。未配置远程仓库。
