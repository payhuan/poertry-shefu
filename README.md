# 诗词射覆

本地运行的 React + TypeScript 诗词游戏。支持两人共用一台设备轮流出题，也支持一人与本地系统对战。游戏运行时只读取项目内的静态题库，不连接在线判题服务。

## 启动

需要 Node.js 22.13+ 和 pnpm 12。项目自带分块压缩的完整 SQLite 题库；首次启动无需重新下载诗词数据。首次查询会在本机拼接并解压题库，可能需要稍等。

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

浏览器打开终端显示的本地地址，默认是 `http://127.0.0.1:5173/`。
SQLite 查询由本地服务提供，因此不能直接双击 `index.html` 启动游戏。

生产构建和规则测试：

```powershell
pnpm build
pnpm test
```

## 玩法

出题者提供上一句诗、目标字数和指定字。指定字**不能**出现在上一句中。答题者给出的新句须具有指定字、与上一句共享至少一个其他汉字、符合目标字数，并被题库收录。标点和空格不计字数，繁简体可互通；答案不受出题者私有参考答案限制。

答对得 1 分，并将答句带入下一轮。主动揭晓一条参考答案视为本题失败，原出题者重新出题。超时也不计分。本地双人模式中，格式正确但题库未收录的答句可以提交双方复核；系统模式无法人工核实未收录诗句，会提示继续修改或揭晓参考答案。

单人模式的系统对手使用同一套本地题库和出题规则。难度控制系统答题成功率：轻松 55%、标准 72%、挑战 90%。系统未答出时，本题失败并由原出题者重新出题。

系统出题会在设定的字数范围内随机尝试目标字数，五字和七字题出现机会较高；若抽中的字数没有可用答案，会改试其他允许字数。

新对局默认“常见诗词优先”：系统出题和“换一句”会优先从《唐诗三百首》《宋词三百首》及带课本标签的作品中选句；也可在设置中改为“全题库随机”。若上一回合承接的句子或题目限制无法匹配常见作品，仍会从全题库选可解的答案。两种设置下，玩家都可使用题库内任意符合规则的诗句作答。这是基于选本和标签的熟悉度偏好，不是实时人气排行榜。

本机通过 localStorage 保存当前对局快照，使用 IndexedDB 保存已结束对局。刷新后可继续，结算页支持导出文本记录。请不要清除浏览器站点数据，以免丢失本地存档。

点击题面或结果中的“出处”可在弹窗中查看对应全诗。全诗保存在本地 SQLite 题库中。

顶部“繁體 / 简体”按钮可切换诗句、线索、出处及全诗的字形，也会转换当前未提交的输入内容。简体和繁体作答使用同一套判题规则；字形选择保存在本机，刷新后仍然有效。

## 题库与来源

题库由 [chinese-poetry/chinese-poetry](https://github.com/chinese-poetry/chinese-poetry) 的固定提交 `b8594f81a89752241442f2ce267d6f66f96704ee` 构建。导入该版本全部 58 份唐诗、255 份宋诗和 22 份宋词 JSON，并保留《唐诗三百首》《宋词三百首》选集标签。游戏允许 2–15 字诗句；超出字数范围或损坏的片段不会进入可作答索引。未命中仍不等于诗句不存在。

`data/source-manifest.json` 锁定原始文件、Git blob 校验值与提交；`scripts/build-corpus.mjs` 可重建 SQLite 数据库、来源索引和质量报告。重建时运行：

```powershell
pnpm corpus
```

该命令会从上述固定提交下载源 JSON，校验 Git blob 后生成 `public/corpus/poetry.sqlite.br.part*`，每块不超过 32 MB，并删除下载缓存。首次查询时本地服务将数据库解压到系统临时目录，项目目录只保留压缩分块；浏览器只接收查询结果，运行游戏不连接互联网。`data/quality-report.json` 记录导入数量、重复和过滤情况。分发时保留了原仓库的 MIT 许可文本 `public/corpus/LICENSE.txt`，并在每条诗句中记录源文件、作品索引、作者与题名。

## Git

本项目使用本地 Git 仓库，源码、锁文件、构建脚本、固定数据版本和游戏题库已纳入版本管理。`node_modules/`、`dist/`、测试输出与原始数据缓存由 `.gitignore` 排除。未配置远程仓库。
